# Nightly failure triage: 36532581294

The manual run on main `bd9c1172` failed independently of local UI changes.
Run: https://github.com/arkadianet/ergo/actions/runs/36532581294

## Findings and repairs

* **Parser acceptance:** sigma-state 6.0.2 rejects invalid DeserializeRegister
  IDs, OptionGet receivers, ByIndex receivers / pre-v3 index types, and unbound
  ValUse references. Rust now hard-rejects these when their types or binding
  absence are known. These exceptions must not become soft-fork wraps. Nested
  boxes can share Scala's binding store, so their unknown bindings remain
  conservative; positive fixtures exercise sharing in both directions.
* **ByIndex invariant:** before v3, Scala writes an Upcast of a constant without
  the cast, then reinserts an Int cast while reading a Byte/Short collection
  index. The comparison now models that exact context. Explicit cast chains
  still strip one level per pass. Other type/value drift must still fail.
* **Retained SBox context:** the constant crash consumes 150 of 376 bytes.
  Scala and Rust both write the exact 150-byte prefix, and both reject that
  prefix without the original suffix. A nested size-delimited tree can inspect
  beyond its declared boundary before a validation failure rewinds the reader.
  The harness classifies this as WriteRejected only for retained-box values,
  with a nonempty suffix and byte-identical consumed prefix. Changed output,
  truncated output, and failures without trailing context remain bugs.
* **Scheduled run 36539074602 (same day, main `bd9c1172`):** replaying its
  crash inputs against this branch left two failures. The transaction crash is
  a node accept-invalid: a `ConcreteCollection` item whose constant type differs
  from the declared element type. sigma-state 6.0.2 rejects it with an
  `AssertionError`, including inside a sized tree, so the parser now
  hard-rejects a mismatched constant item. The box-candidate crash is the
  Bug #19 reshape in its successful form: the re-encoded creation height becomes
  new lookahead for a 0-byte sized body, which then parses structurally. Scala
  re-serializes the input to the same bytes. The harness now exempts that
  wrap-to-structural flip only; drift that keeps or gains opacity is still a Bug.
  Scala rejects the reshaped bytes: `OptionGet` over an `Apply` whose callee is
  not a function has `NoType`.
* **Branch fuzz run 36549229095:** two more node divergences.
  `TaggedVariableSerializer.parse` reads a type after the variable id, but the
  node read only the id. That misaligned the rest of the stream in both
  directions: Scala accepts `SigmaAnd(TaggedVar, TaggedVar)`, which the node
  rejected. The parser and writer now carry the type. Separately, a nested box
  script rooted at `Apply` of a constant was accepted, though Scala types it
  `NoType` and fails rule 1001. `SigmaType::NoType` now models Scala's
  `Apply.tpe`: a function callee gives its range, a collection callee its
  element type, and any other callee with a known type gives `NoType`, which
  every cast-checking parent and rule 1001 reject. It is never read or
  written.
* **Memory investigation:** the saved 95-byte OOM artifact does not reproduce
  excess memory alone. The failing ASan run reported 2,071 MB RSS after about
  6.1 million executions, with approximately 31.5 MB live heap and 67.6 MB
  quarantined. Untrusted collection counts previously reserved large buffers
  before validating the first element. Initial reservations are now capped at
  64 elements and grow with successfully parsed values; acceptance limits are
  unchanged. The 2,048 MB fuzz RSS limit remains enforced. A full ASan run is
  required to establish whether this addresses accumulated allocator memory.
* **CI setup:** scala-cli does not provide sbt. The workflow now installs an
  sbt runner before publishing the reference dependencies on a cold runner.

Wire vector files are copied byte-for-byte. Each one has a companion
`<op>.jvm.tsv` holding our own JVM verdict for every entry, written by
`scripts/santa_wire_oracle/SantaWireOracle.scala` on sigma-state / ergo-core
6.0.6. The test always requires SANTA's expectation and our JVM verdict to
agree. `KNOWN_DIVERGENCES` pins independently reproduced node/JVM differences:
every listed `(relative file, entry)` must still differ, and every other entry
must agree on all three sides. A node fix must remove its entry from the list;
missing entries and duplicate exceptions fail the test. Consensus-boundary
expectations come from these external Scala fixtures, never a Rust self-oracle.

To add a family: copy its `<op>.json` from SANTA, then write its verdicts:

```bash
f=test-vectors/santa/wire/v6/authored/<op>.json
scala-cli run -q scripts/santa_wire_oracle/SantaWireOracle.scala -- "$f" > "${f%.json}.jvm.tsv"
```

The seven additional v6 wire families are `Box.register_evaluated_values`,
`Transaction.register_evaluated_values`, `Transaction.extension_evaluated_values`,
`Box.tree_parse_acceptance`, `Transaction.tree_parse_acceptance`,
`ErgoTree.unparsed_soft_fork_roundtrip`, and
`ErgoTree.unparsed_soft_fork_option_constant`. All 360 entries in 35 wire files
agree with our independently regenerated JVM verdicts. Fifteen differences
reproduce through the production codecs. The three unparsed-soft-fork entries
are agreement controls: vixen strips their size flag before parsing, whereas
production `read_ergo_tree` / `write_ergo_tree` preserve their original bytes.

All 41 transaction files (311 entries) are copied byte-for-byte from SANTA.
Their companions are generated by
`scripts/santa_tx_oracle/SantaTxOracle.scala`, independently invoking ergo-core
6.0.6 `validateStateful` with the `santa-transaction/v1` provided context.
The oracle parses transactions under the parameters' block version from v4
up, reads UTXO boxes and validates outside a version context, preserves the
newest-first header order, and honors all seven economic parameters plus the
optional voted block version. Its testnet chain settings are extracted from
SANTA's `chain-testnet.conf`; EIP-27 is disabled as in the contract.

Run from the repository root with Scala CLI 1.17.1 (pinned in
`.github/ci-tools.toml`) and a JDK. For example, install both at user level:

```bash
~/.local/bin/mise install scala-cli@1.17.1 java@temurin-21
# Some mise releases install this binary as scala-cli-x86; if needed, add a
# scala-cli symlink beside it in the installation directory reported by mise.
for f in test-vectors/santa/transaction/*/*/*.json; do
  ~/.local/bin/mise exec scala-cli@1.17.1 java@temurin-21 -- \
    scala-cli run -q --server=false scripts/santa_tx_oracle/SantaTxOracle.scala -- "$f" \
    > "${f%.json}.jvm.tsv.tmp" && mv "${f%.json}.jvm.tsv.tmp" "${f%.json}.jvm.tsv" || exit 1
done
```

The output format is `entry<TAB>valid<TAB>cost`, with `null` cost on rejects.
JVM rejection diagnostics go to stderr; set `SANTA_TX_ORACLE_TRACE=1` to include
stack traces. Setup and decode failures abort regeneration. Neither oracle
reads SANTA's expected results. Both dependencies use the GitLab Maven
repository declared in the scripts; a local publication from the Scala node
v6.0.6 tag is also supported where ergo-core is unavailable remotely.

All 311 transaction expectations agree with our JVM oracle, including costs
on 231 accepts. The test pins 50 consensus differences: 28 JVM accepts/node
rejects, 21 JVM rejects/node accepts, and one accept-cost difference. It drives
`read_transaction` and `validate_transaction_parsed_with_group_elements` with
scripts enabled and compares `total_block_cost`. Decode failures count as
rejects for this consensus comparison: the 11 entries where both sides reject
need no exception, even though SANTA's runner grading distinguishes a decode
failure from a validation rejection. Panics remain test failures.

The formerly unclear `c2-twin-output-register-reject#46` is confirmed:
JVM `verifyOutput` calls `BoxUtils.minimalErgoAmount`, which serializes
`ErgoBox.bytes`; `ConcreteCollectionSerializer` reaches `TypeSerializer` for a
function type in the ambient default (1, 1) context and throws `MatchError`.
The production Rust validator accepts at cost 12102.

The Scala node v6.0.7 build uses sigma-state 6.0.7 and release-tagged ergo-core
6.0.7, so these 6.0.6 fixtures do not certify v6.0.7 parity. The sigma update
adds type-depth and zero-width-collection guards, potentially affecting
constant/register/extension and tree soft-fork families, including
`evaluated-values-spend` and `deserialize-substitution-spend`. The core update
adds height-gated data-input and storage-rent output-index uniqueness checks,
which can affect multi-input and storage-rent families at activation heights.
See the upstream [node build](https://github.com/ergoplatform/ergo/blob/v6.0.7/build.sbt),
[sigma changes](https://github.com/ergoplatform/sigmastate-interpreter/compare/v6.0.6...v6.0.7),
and [core changes](https://github.com/ergoplatform/ergo/compare/v6.0.6...v6.0.7).

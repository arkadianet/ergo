# Wallet interoperability fixtures

`scala_6_0_6.json` was generated on 2026-10-03 by the real Scala wallet and
sigma-state 6.0.6 implementations. The reference node tag `v6.0.6` resolves
to `23aabead88774d27f2c9190ace3c9abbc8f1d5cb`. The generator uses fixed salts,
IVs and public test phrases so the fixture is reproducible. These are test
wallets; never send funds to their addresses.

The script exercises `AES.encrypt`, `EncryptedSecret`'s Circe codec,
`Mnemonic.toSeed`, SDK master/child derivation and `ErgoAddressEncoder`.
It pins the historical encrypted-stream field split, absent cipher
algorithm/mode fields, a null legacy flag, the modern EIP-3 address and the
pre-1627 leading-zero derivation branch. Rust tests additionally remove the
legacy flag to cover old imports. They do not derive expected bytes using
the Rust implementation. The fixture includes every private-key/chain-code
intermediate along the legacy EIP-3 path, including its stripped leading zero.

Install Java 17, sbt and scala-cli. Publish the reference wallet first because
`ergo-wallet` 6.0.6 is not on Maven Central:

```sh
git clone --depth 1 --branch v6.0.6 https://github.com/ergoplatform/ergo.git /tmp/ergo-wallet-reference
git -C /tmp/ergo-wallet-reference rev-parse HEAD
cd /tmp/ergo-wallet-reference
sbt "ergoWallet/publishLocal"
```

From this repository, regenerate and compare:

```sh
scala-cli run scripts/jvm_wallet_oracle/WalletOracle.scala --server=false --jvm 17 > /tmp/scala-wallet.json
diff -u test-vectors/wallet/scala_6_0_6.json /tmp/scala-wallet.json
```

The reverse check unlocks a freshly written Rust secret file and compares
the Scala-derived master key, rather than just comparing JSON:

```sh
export ERGO_WALLET_INTEROP_FILE=/tmp/rust-wallet.json
cargo test -p ergo-wallet --test it rust_generated_file_exports_for_scala_verification
scala-cli run scripts/jvm_wallet_oracle/WalletOracle.scala --server=false --jvm 17 -- verify "$ERGO_WALLET_INTEROP_FILE" test-rust-to-scala-pw
```

Both checks run in the `Scala wallet interoperability` PR job. Feature-gated
multi-signature and proving consistency targets also run explicitly in CI.

## Deferred selection oracle

The remaining ignored wallet oracle is the compact box-selection scaffold.
Its owner is the wallet crate maintainers; its external source is Scala
`DefaultBoxSelector` / `ReplaceCompactCollectBoxSelector` and their specs in
the pinned reference wallet. Completion requires deterministic candidates,
ERG/token targets and Scala-selected inputs/change for exact, insufficient,
replacement and compaction cases, then an enabled integration test. The Rust
compact selector currently delegates to its default selector; it does not
claim the reference compaction policy. Existing local selection tests prove
the implemented policy's invariants, not Scala compaction parity.

## Reduced transactions and cold transport

`reduced_scala_6_0_7.json` is generated by
`scripts/jvm_reduced_transaction_oracle/ReducedTransactionOracle.scala` using
sigma-state **6.0.7** and AppKit **6.0.1**. Reduction uses the real SDK
`ReducingInterpreter`; serialization, cold signing and response parsing also
run through AppKit's `ColdErgoClient`, `parseReducedTransaction`, `signReduced`
and `parseSignedTransaction`. Fixed public scalars 1–3 supply fixture secrets;
proof nonces are random, so regenerated proofs need not be byte-identical.

The eleven cases cover trivial true, DLog, DH tuple, AND, OR, 2-of-3 threshold,
HEIGHT/output context, a Spectrum N2T swap, an AgeUSD bank mint with an oracle
data input, a ZeroJoin full-mix DH-tuple spend, and a nonempty `getVar` context
extension. Spectrum/AgeUSD use the checked-in complete contracts in
`test-vectors/ergoscript/cannonq/significant15/`; their transactions are
constructed SDK fixtures, not historical on-chain transactions. ZeroJoin uses
the full-mix contract from `anon92048/ergo-mixer-demo` at
`c4df6ad3758aa5bad259b71735891f15439f5753` (`ErgoMix.scala`). The fixture records
input/data boxes, source text, exact reduced bytes, cumulative input costs,
aggregate reduction cost, crypto verification cost, and independently signed
proofs.

`ReducedInput.cost` is the SDK's cumulative running block cost, not a cost to
sum across inputs. `reduction_cost` includes interpreter initialization,
input/data-input/output access, token access and script evaluation. AppKit's
signed `crypto_cost` is an additional cost; signing checks the sum before
producing proofs. Rust reductions, including reductions made without secrets,
must match every cumulative cost and the complete reduced wire bytes. The SDK
also checks identical reductions with active parameter block version 4 and
physical pre-header version 3: activation follows parameters independently of
the script-visible pre-header, as required for transitions within an epoch.

Transport fields follow [EIP-19](https://github.com/ergoplatform/eips/blob/5cb67888f59683b1d4f3a382fa3dabe208088105/eip-0019.md)
and [EIP-20](https://github.com/ergoplatform/eips/blob/5cb67888f59683b1d4f3a382fa3dabe208088105/eip-0020.md).
The CSR/CSTX envelopes use the low-density chunk boundaries from
[Ergo Wallet App `ColdWalletUtils.kt`](https://github.com/ergoplatform/ergo-wallet-app/blob/beeecb1009e26c6ea9b506d5fca3a4efb3f79f9e/common-jvm/src/main/java/org/ergoplatform/transactions/ColdWalletUtils.kt):
split the compact inner JSON into string slices, then JSON-escape each slice
inside a `CSR` or `CSTX` envelope. Pagination uses one-based `p` and total `n`;
single-page envelopes omit them. The inner request's `reducedTx` and complete
input boxes use **standard padded Base64**. Static ErgoPay `ergopay:` links
and dynamic request `reducedTx` use **URL-safe Base64**.

The response bytes have an important SDK distinction: AppKit
`SignedTransactionImpl.toBytes()` appends a VLQ unsigned crypto-cost to the
ordinary node transaction. `scala_signed_hex` contains the node transaction;
`appkit_signed_hex` and the CSTX `signedTx` contain that transaction **plus the
cost trailer**. This trailer is AppKit's SDK wrapper; EIP-19 does not prescribe
it for every consumer. The oracle separately tests the canonical node
transaction and the actual AppKit response form. It parses the SDK trailer
explicitly, rejects extra or missing bytes in that form, and verifies that it
does not change the transaction ID or message to sign. A parser that silently
accepts a transaction prefix would miss this AppKit-specific distinction.

The Rust integration tests reconstruct reversed-order CSR/CSTX pages, preserve
box order/IDs and context extensions, round-trip both ErgoPay forms, verify
AppKit proofs, and export Rust proofs and both signed byte forms. Missing,
duplicate and mixed-direction QR pages are rejected in the transport harness.
EIP-19 envelopes provide no authenticated session identifier; mixed requests
with the same page count still require transaction/participant validation.
The independent sigma-rust **0.28.0** oracle checks wire/cost parity and proofs,
and actually renders QR modules into grayscale images with `qrcode` then
scans those images with `quircs`. These SDK/QR dependencies live in a separate
oracle workspace; only Base64 is a wallet dev-dependency. These checks establish
serialization and synthetic image round trips, not real-device camera testing.

Regenerate and check with Java 17 and scala-cli:

```sh
scala-cli run scripts/jvm_reduced_transaction_oracle/ReducedTransactionOracle.scala --server=false --jvm 17 > /tmp/reduced-scala.json
python3 scripts/check-reduced-oracle.py test-vectors/wallet/reduced_scala_6_0_7.json /tmp/reduced-scala.json
ERGO_REDUCED_PROOFS_FILE=/tmp/rust-reduced-proofs.json cargo test -p ergo-wallet --test it reduced_transaction_oracle
scala-cli run scripts/jvm_reduced_transaction_oracle/ReducedTransactionOracle.scala --server=false --jvm 17 -- verify /tmp/rust-reduced-proofs.json
CARGO_TARGET_DIR=/tmp/sigma-rust-reduced-oracle cargo run --manifest-path scripts/sigma_rust_reduced_oracle/Cargo.toml --locked -- test-vectors/wallet/reduced_scala_6_0_7.json /tmp/rust-reduced-proofs.json
```

The comparison drops only nonce-dependent proofs, signed bytes and response QR
pages. Request QR pages, ErgoPay encodings, reduction bytes, IDs and all costs
must remain exact. Ordinary `Prover::sign` retains its existing script gate;
context-sensitive direct signing is a separate follow-up review.

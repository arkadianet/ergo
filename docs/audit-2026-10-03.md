# Rust node codebase audit — 3 October 2026

Audit target: commit **5d62fd5851e74fcb965b4aba50e1b423127f46f1**, workspace version **0.10.0**, Rust **1.95.0**, Linux. Review began on 2 October and completed on 3 October in Australia/Brisbane.

This is the historical review of the stated commit. Remediation is tracked in
[audit-remediation-todo.md](audit-remediation-todo.md); findings below describe
the reviewed baseline, not the updated implementation.

## Assessment

This repository has strong foundations: deliberate crate boundaries, an explicit consensus compatibility policy, substantial external-oracle coverage, established cryptographic dependencies, extensive operator documentation, and a serious CI/fuzzing investment. The code shows considerable care in the difficult protocol details.

It does **not yet meet the requested standard of exceptional Rust engineering throughout**. The most consequential shortcomings are where independently sound components interact: asynchronous persistence with foreground header writes, failed incremental commits, cancelled metered reads, detached workers, and APIs that turn failures into valid-looking data. These deserve attention before broad stylistic refactoring.

Six high-priority findings are supported by source analysis or small local reproductions. There are ten further medium-priority findings and several investigation/evidence gaps below. Priority expresses remediation order, not a formal vulnerability rating. Several findings require a storage error, shutdown, embedding multiple nodes, or downstream API misuse; they are not all remotely exploitable.

This was a broad, sampled audit across all 19 crates, with parallel deeper reviews of runtime/network/API/indexer, consensus/compiler/serialization, and storage/wallet/mining. It was not a line-by-line review of approximately 368,000 source lines, including inline tests. Performance was assessed through implementation and existing measurement reports; this audit did not benchmark live-mainnet throughput, run a live Scala node, repeat the nightly fuzz campaign, verify every cryptographic implementation, or test other operating systems. Browser UI/accessibility and deployment infrastructure were not reviewed deeply. Findings distinguish reproduced behavior, source-confirmed defects, and unverified risks.

No implementation files were changed. This report is a local review artifact; no issue, commit, PR, deployment, or external message was created.

## High-priority findings

### F01 — Competing persistence paths overwrite each other's chain metadata

**Priority P1. Source-confirmed; the precise race was not exercised in a controlled runtime reproduction.**

Locations: [job snapshot capture](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-state/src/store/mod.rs#L3739), [background metadata write](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-state/src/persist.rs#L928), [batched header metadata write](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-state/src/header_store.rs#L643), [direct header metadata write](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-state/src/header_store.rs#L790), [foreground header entry point](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-state/src/store/mod.rs#L2700).

Each queued block-persistence job captures the entire foreground chain state. The worker later replaces the complete CHAIN_STATE_META row with that snapshot. Foreground header transactions also replace the complete row from their in-memory chain state. Neither path merges the other path's committed fields or establishes a queue-drain barrier.

Two permitted orderings violate the committed-state contract:

1. A block job captures full tip H and selected header K. A foreground header transaction selects K+1. The older block job then commits its snapshot, regressing the persisted header selection to K while the header index can still represent K+1 or its fork.
2. Foreground state has applied H while the persist worker has committed only H−1. A header transaction copies the foreground full tip H into CHAIN_STATE_META before H's AVL/state/chain-index transaction commits. A reader or crash can therefore observe a supposedly committed H paired with H−1 state.

Production header processing delegates directly through the state backend and header batch methods; the reviewed paths have no hidden pipeline flush. The worker's CommittedHeights bookkeeping is diagnostic context, not a metadata merge. redb serializes transactions, but serialization alone does not prevent stale precomputed snapshots from replacing newer fields.

**Remediation:** define ownership of header versus full-state fields inside each transaction, preserving the current committed fields belonging to the other writer. Alternatively, route both kinds of updates through a single persistence owner. Comparing heights alone is insufficient because best-header fork selection can change at the same height.

**Acceptance test:** pause the persist worker at an explicit barrier, queue block apply, commit header advancement and a same-height fork change, inspect every committed snapshot, then release the old job. Full tip, AVL root and chain index must agree at every boundary; the selected header must survive. Reopen the database at both intermediate boundaries.

### F02 — A failed persistence batch does not stop later dependent deltas

**Priority P1. Source-confirmed.**

Locations: [worker error arm](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-state/src/persist.rs#L725), [incremental AVL writes](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-state/src/persist.rs#L849), [notification drain](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-state/src/store/mod.rs#L922).

On execute_batch failure, the worker records a reliable sticky error and attempts per-job error notifications, then continues receiving and committing later jobs. Those jobs are incremental changes computed against foreground state that already contains the failed batch.

If batch N fails and a later batch succeeds, the later transaction can publish a later tip without all predecessor AVL, undo, chain-index or wallet changes. The sticky error protects flush callers but does not prevent those transactions. The result channel can also drop error notifications when full; foreground draining relies on that channel rather than checking the reliable failure state.

**Remediation:** make the first failed batch terminal for that worker. Reject subsequent writes and sends through shared reliable failure status, and rebuild or shut down against the last consistent committed state. A later successful storage operation must not make a dependent delta safe to apply.

**Acceptance test:** commit H, deterministically fail H+1, then supply an otherwise valid H+2. No H+2 writes may land; all later send/flush operations must report the failure. Repeat with a saturated notification channel. The existing consecutive-failure test measures diagnostics, not this terminal integrity property.

### F03 — Cancelled P2P reads retain body bytes after releasing their budget

**Priority P1. Reproduced locally with a small valid frame.**

Locations: [local admission/permit ownership](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-p2p/src/connection.rs#L455), [retained connection buffer](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-p2p/src/connection.rs#L207), [read versus outbound selection](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-node/src/peer_loop.rs#L480).

The read buffer belongs to Connection, but the remote-address admission claim, reader slot and byte permits belong to the read future. An outbound message winning select cancels that future and releases the claims/permits while leaving the partially accumulated frame in Connection.

A loopback harness supplied a valid 128 KiB payload with its last byte temporarily withheld. Cancellation released all 131,085 charged bytes; supplying the last byte then completed the original 131,072-byte payload, proving the prefix had survived uncharged.

The next read reacquires a charge, but retained memory is unaccounted for during outbound writes and subsequent admission waits. This breaks the advertised aggregate budget and the slot pool's argument about bounded buffered readers. The existing cancellation test covers a bare header and explicitly expects full release; it misses accumulated bodies.

**Remediation:** give the buffered frame and its admission state the same lifetime. Transfer permits to the completed payload or release them only when buffered bytes are discarded. A separate persistent reader and writer is another design option.

**Acceptance test:** retain a substantial partial valid frame, cancel through the outbound branch, and assert both byte and slot accounting across cancellation, waiting, resume, completion and disconnect. Include multiple connections and independent address admission.

### F04 — The compiler's parse-depth guard does not bound constructed AST depth

**Priority P1. AST-depth bypass reproduced; a process abort was not attempted.**

Locations: [claimed depth invariant](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-compiler/src/parse/mod.rs#L49), [iterative infix construction](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-compiler/src/parse/operators.rs#L191), [iterative suffix construction](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-compiler/src/parse/block/lambda.rs#L323), [recursive binder](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-compiler/src/binder.rs#L125), [public v1 compiler handler](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-api/src/v1/script/handlers.rs#L176).

The 128 limit counts recursive parser entry, but flat infix/suffix chains are assembled iteratively into deeply boxed ASTs. The later binder and transforms recurse over these trees under the assumption that parsing has bounded their depth.

The offline public parse API accepted 1,024 subtraction operands in 4,093 source bytes and produced AST depth 1,024. This is well within the v1 64 KiB source limit. The Scala-compatible address compilation route has no explicit equivalent source cap.

**Remediation:** track actual AST height during construction, covering infix, suffix and stable identifier chains. Reject before constructing a tree whose later traversal or recursive destruction is unsafe. Wire-tree reparse bounds occur too late to protect earlier compiler phases.

**Acceptance test:** flat infix, selectors, repeated calls and mixed chains; exact boundary tests; bounded-stack compiler and destruction tests. Source byte caps are an additional limit, not a substitute for structural limits.

### F05 — Wallet initialization does not publish its encrypted seed file atomically or durably

**Priority P1. Source-confirmed failure window; power-loss behavior was not exercised.**

Locations: [secret-file creation and direct write](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-wallet/src/storage.rs#L571), [success/cache update](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-wallet/src/storage.rs#L586), [initialization guard](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-node/src/node/wallet_bridge/commands/admin.rs#L154).

Creation writes directly to the final UUID JSON filename, without syncing the file or directory and without temporary publication. A failed/interrupted write can leave a truncated final file; power loss after success can lose content or its directory entry. File discovery treats an existing secret file as initialized, blocking ordinary init/restore retry, while truncated JSON cannot unlock.

The Unix 0600 create_new behavior is a good permission safeguard. It does not establish atomic publication or persistence. Seed material has a different recovery requirement from chain data that can be downloaded again.

**Remediation:** write a restrictive temporary file in the same directory, sync it, atomically publish without replacing an existing wallet, and sync the containing directory where supported. Cache success only after publication completes. Ensure discovery excludes unfinished temporary files and recovery is explicit.

**Acceptance test:** injected errors after creation, partial write, sync and publication. On reopen, the directory must represent either a complete unlockable wallet or a safely retryable uninitialized wallet, never a selected truncated secret file. Cover supported platforms.

### F06 — The documented script authentication option is not connected to production configuration

**Priority P1. Source-confirmed configuration defect.**

Locations: [documented option](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-api/src/v1/script/mod.rs#L18), [TOML API schema](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-node/src/config/toml_sections.rs#L164), [production ScriptState assembly](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-api/src/server/mod.rs#L1011).

The module tells operators to use [api.script] require_api_key = true. TomlApi has no script field and permits unknown fields. Production router construction always supplies ScriptConfig::default(), which leaves the playground public.

Thus the described hardening setting is silently ignored. Public endpoints are an intentional default; the defect is that the documented control cannot change that default.

**Remediation:** carry validated script settings through TOML, resolved NodeConfig and API assembly. Reject unknown security settings and test the actual node boot path. Remove the unsupported promise until this path exists.

**Acceptance test:** load the option with a configured key, boot the API and verify all seven playground endpoints require authentication. Test misspelled keys and invalid cost settings.

## Medium-priority findings

### F07 — Clean shutdown can return success after a persistence failure

**Priority P2. Reproduced with the existing pending-failure helper.**

Locations: [shutdown_cleanly](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-state/src/store/mod.rs#L1062), [pipeline Drop](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-state/src/persist.rs#L1209), [node propagation contract](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-node/src/node/action_loop.rs#L338).

The storage method drops the pipeline and returns the result of a final empty durable transaction. Pipeline Drop logs errors and join failures instead of returning them. A pending injected persistence error consequently produced Ok(()) from shutdown_cleanly.

**Remediation/test:** add explicit fallible drain/join, preserve the first failure while still attempting final flush, and retain Drop for best-effort cleanup. Pending error, failed final batch and worker panic must fail explicit shutdown; a successful drain must preserve all queued blocks.

### F08 — Wallet rescans and their database ownership are outside node shutdown supervision

**Priority P2. Source-confirmed lifecycle gap; no blocked-rescan shutdown experiment was run.**

Locations: [rescan task creation/cancellation](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-node/src/node/wallet_bridge/commands/admin.rs#L298), [discarded rescan handle](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-node/src/node/wallet_bridge/commands/admin.rs#L338), [detached wallet writer](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-node/src/node/boot/api_wiring.rs#L279), [RunHandle shutdown](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-node/src/node/handle.rs#L174).

A rescan captures database, chain and store Arcs in spawn_blocking, discards its handle and returns. Its cancellation predicate checks rescan ownership, not node shutdown. Explicit shutdown does not cancel/join this worker or own the wallet-writer handle.

Shutdown can therefore finish its supervised work while an active rescan continues holding and writing the database. Immediate reopen can fail, and runtime teardown can still wait for the blocking task.

**Remediation/test:** supervise both workers, stop command admission, cancel rescans between atomic block operations, join them before final close, and test a barrier-controlled rescan followed by shutdown and immediate reopen.

### F09 — Biased action selection can starve API and mining submissions

**Priority P2. Source-confirmed scheduling defect under continuously ready peer input.**

Location: [action-loop selection](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-node/src/node/action_loop.rs#L137).

Peer events precede transaction and mining receivers in a biased select. A 64-event batch cap bounds one branch's work but does not make later branches eligible if the peer queue stays ready. The one-loop-tick latency promise in the comment is therefore unsupported.

**Remediation/test:** keep shutdown priority and provide explicit fairness for ready work channels, such as rotating priority or per-source service budgets. A continuously active peer producer must not prevent an API transaction or miner reply from being served within the documented budget. [Tokio's select documentation](https://docs.rs/tokio/latest/tokio/macro.select.html#fairness) assigns fairness responsibility to the caller when biased selection is used.

### F10 — Indexer storage errors can appear as successful zero balances

**Priority P2. Source-confirmed error-contract defect.**

Locations: [indexer error conversion](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-indexer/src/handle.rs#L364), [HTTP balance conversion](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-api/src/blockchain/balance.rs#L90).

address_balance logs a read error and converts it to None; the API converts None to the default zero confirmed balance and HTTP 200. Several other infallible index methods similarly turn read/decode errors into empty or missing results. A CaughtUp status cannot guarantee that every individual row is readable.

**Remediation/test:** use Result<Option<T>, Error> and fallible page methods consistently. Missing data can still mean zero; failed reads must return an internal/unavailable response and degraded health. Corrupt an address row while the indexer remains caught up and verify the route does not claim a zero balance.

### F11 — Public register mutation breaks cached-byte invariants

**Priority P2. Source-confirmed API defect; no current production mutation was found.**

Locations: [public parsed registers/private cache](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-ser/src/ergo_box/mod.rs#L73), [writer uses the cache](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-ser/src/ergo_box/candidate.rs#L27), [evaluation uses parsed registers](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-validation/src/tx/script/eval_box.rs#L37).

Safe downstream code can mutate additional_registers while register_bytes remains unchanged. Serialization and content-addressed IDs then describe the old values, while script evaluation reads the new parsed values. The analogous SpendingProof extension is already encapsulated to avoid this problem.

**Remediation/test:** make parsed registers private, expose read access and a fallible replacement operation that rebuilds both representations together. A register replacement must change serialized bytes/IDs and agree with decoding those bytes. Reject invalid replacements without changing the object.

### F12 — Context-extension serialization accepts counts the decoder rejects

**Priority P2. Source-confirmed writer/reader mismatch, already demonstrated by an existing test.**

Locations: [writer permits up to 255](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-ser/src/input/context_extension.rs#L76), [reader rejects above 127](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-ser/src/input/context_extension.rs#L135), [test preserves writer behavior](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-ser/src/input/context_extension.rs#L1149).

The source records that Scala's writer also refuses counts above 127, yet the Rust writer accepts 128–255. It can therefore return success with bytes that its own transaction decoder refuses. The reader-negative test constructs 128 entries with the real writer and expects successful emission, preserving this inconsistency.

**Remediation/test:** share the count cap, obtain Scala writer boundary evidence, and reject unsupported counts before emission. Construct malformed reader-test bytes directly. Test 127/128/255 and constructor propagation. High-bit variable IDs are a separately documented Scala-shared asymmetry and are not included in this finding.

### F13 — Process-global API stores and once-only workers are not node-scoped

**Priority P2. Source-confirmed embedding/restart defect; single-node CLI scope is narrower.**

Locations: [global API service assembly](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-api/src/server/mod.rs#L906), [once-only event worker](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-api/src/v1/realtime/ws.rs#L415), [once-only depth sampler](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-api/src/v1/mempool_depth.rs#L218).

The process-global bus, depth ring and webhook engine outlive individual nodes. Detached worker flags bind samplers to the first NodeReadState and cannot restart after its runtime disappears. Multiple nodes can share observations and registrations, including across networks.

**Remediation/test:** inject a node-owned API-services object with cancellation and join handles. Router construction should assemble routes without starting process-global work. Test two independent nodes and a same-process runtime restart.

### F14 — Secret-lifetime guarantees exceed the implementation

**Priority P2. Source-confirmed ownership/documentation gaps, not proof of ordinary signing compromise.**

Locations: [plain cloneable commitment nonce](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-wallet/src/proving/hints.rs#L57), [plain proving scalars](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-wallet/src/proving/sigma/tree.rs#L65), [mnemonic buffers](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-wallet/src/mnemonic.rs#L49), [codemap guarantee](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/docs/codemap/ergo-wallet.md#L158), [swap/crash-dump claim](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-wallet/src/encryption.rs#L8).

OwnCommitment is Clone and owns an ordinary nonce array; prover leaves hold ordinary scalars; entropy and seed paths include ordinary buffers. These do not support the claim that all leaf scalars and commitment randomness zeroize on drop. Wiping on drop also does not itself prevent secrets being copied to swap or a crash dump while alive.

**Remediation/test:** define an inventory of secret owners, use zeroizing storage at creation and on error paths, minimize copies, consider bip39's zeroize feature, and make the documentation precise. Preserve the useful Debug-redaction tests, but do not equate redaction with memory erasure. Request-local scalar/HMAC residuals already documented elsewhere should be represented consistently.

### F15 — Wallet interoperability fixtures and extra proving targets are missing from normal assurance

**Priority P2. Confirmed test/evidence gap, not proof of incompatible cryptography.**

Locations: [placeholder AES/PBKDF2 vectors](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-wallet/tests/it/aes_gcm_pbkdf2_oracle.rs#L29), [ignored storage compatibility](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-wallet/tests/it/storage_oracle.rs#L18), [ignored legacy derivation evidence](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-wallet/tests/it/pre_1627_derivation_oracle.rs#L39), [feature-required test targets](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-wallet/Cargo.toml#L65).

Two encryption-oracle tests retain EXTRACT_FROM_SCALA placeholders. Three storage import/export tests lack their fixtures. A legacy-address oracle is ignored. The two extra proving targets require test-utils; normal workspace CI does not execute them, and all-features Clippy only compiles them.

The extra suites passed in this audit: 33 multisig and 24 internal-consistency cases. That is positive local evidence, not a substitute for keeping them in the gate.

**Remediation/test:** commit reproducible externally generated modern/legacy wallet fixtures and populate expected values, then remove the relevant ignores. Add an explicit feature-test CI leg. Track each unavailable oracle by owner, fixture source and completion criterion.

### F16 — Rustdoc is not clean, and some public claims are stale

## Risks and evidence gaps requiring focused investigation

### R01 — Evaluator value cloning may amplify a shallow program into a large proposition

**High-priority investigation. Bounded exponential growth reproduced; large-scale exhaustion and Scala parity remain untested.**

Locations: [fixed-cost variable cloning](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-sigma/src/evaluator/opcodes/binding.rs#L43), [fold accumulation](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-sigma/src/evaluator/opcodes/collection.rs#L388), [owned conjunction construction](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-sigma/src/evaluator/opcodes/sigma.rs#L479), [post-reduction crypto budgeting](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-sigma/src/reduce.rs#L366).

Value and SigmaBoolean recursively own and clone their children. A shallow fold combining its accumulator with itself can double the owned proposition each iteration while opcode charges grow with iterations. The crypto estimate occurs after proposition construction and recursively traverses it.

A small offline public compile/decode/reduce harness confirmed the growth pattern:

| Fold iterations | Serialized tree bytes | Proposition nodes | Proposition leaves | Evaluation JIT units |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 34 | 3 | 2 | 110 |
| 5 | 50 | 63 | 32 | 318 |
| 10 | 70 | 2,047 | 1,024 | 578 |

The reduction completed under an enforcing 100,000-JIT evaluation limit. Full transaction verification also charges crypto afterward; the harness separately estimated 4,090,865 crypto JIT units at ten iterations. This demonstrates intermediate ownership growth, not that the corresponding transaction would be accepted under a particular full verification budget. No exhaustion workload was run.

**Next step:** add bounded allocation-growth fixtures and equivalent Scala verdict/cost evidence. Consider immutable sharing, cached aggregate cost and iterative traversals. A new arbitrary consensus reject limit requires compatibility analysis; avoid introducing one as an unverified safety shortcut.

### R02 — Durability names and comments do not match the effective pipeline mode

[persist.rs](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-state/src/persist.rs#L832) selects Eventual for jobs marked durable, including outside IBD. Nearby comments and API descriptions sometimes promise Immediate. This is separate from redb transaction atomicity: eventual durability can preserve consistency while allowing recent progress to be lost after power failure.

Define and expose the actual mode for IBD and tip operation, document the tolerated crash window, and distinguish enqueued, committed and synchronously durable progress. Test mode transitions against abrupt process termination. Do not infer a fsync guarantee from a durable boolean.

### R03 — Compute endpoints need an aggregate execution bound

Compiler/typecheck/reduce handlers run synchronous work on Tokio workers. Per-client governor limits and consensus execution costs do not prove a global CPU/memory bound, especially across many clients or loopback callers. Native database reads already provide a useful bounded blocking-lane pattern.

Measure maximum-size valid and invalid requests, use bounded admission for CPU work, and retain permits until work actually finishes even when HTTP callers time out. Avoid relying on a timeout to cancel a blocking task that continues running.

### R04 — Global state makes tests and embedded runtimes less deterministic

[SCAN_REBUILD_IN_PROGRESS](https://github.com/arkadianet/ergo/blob/5d62fd5851e74fcb965b4aba50e1b423127f46f1/ergo-node/src/wallet_boot.rs#L75) is process-global. Some tests change it under RESCAN_TEST_LOCK while other tests read through production hooks without the same lock. A previous [performance report](/home/arkadias/Coding/remote/ergo/docs/perf/node-performance-2026-09-26.md) records a parallel failure in this area. The default suite passed in this audit.

Move per-node rescan state into the node/wallet service. Until that refactor, ensure every relevant test participates in shared-state isolation and uses scoped restoration. nextest's process isolation is useful but does not establish same-process correctness.

### R05 — Existing disclosed deployment/compatibility limitations remain relevant

Mode 2 trust-root verification, deferred Mode 4 installation/live soak, Mode 5 external ADProof/reorg assurance, cooperative multisig deferral, webhook DNS-resolution policy, and IPv6 peer-prefix policy merit explicit closure plans. The public README/compatibility policy already discloses major operating-mode gaps; they are not newly discovered bugs.

The nightly archival replay job can skip without REPLAY_NODE_URL, and JVM differential reduction runs remain manual. Preserve honest reporting that skipped external campaigns did not validate those guarantees.

OwnCommitment bags also expose a misuse hazard: cloneable/reusable nonce material is not message-bound or single-use. Ordinary fresh-nonce signing is not implicated by this observation. Native APIs should encode commitment consumption and document low-level compatibility responsibilities.

### Maintainability improvements worth making

- Extract the compiler's large historical deviation/closure narrative from its 1,312-line crate root into a maintained compatibility/design ledger. Keep current public contracts and examples at the entry point.
- Split the 13,331-line evaluator test file and 8,239-line node test file by behavioral domain, maintaining nearby oracle provenance and meaningful test names. Splitting by ownership is more useful than an arbitrary line-limit rule.
- Review the 4,459-line StateStore module around transaction ownership, pipeline state and header/full-tip responsibilities. Smaller modules help only if those contracts become easier to see and harder to violate.
- Replace broad module-level dead_code allowances where the originally deferred seams now have production callers; retain narrow explained exceptions for unavoidable upstream error shapes.
- Establish a small workspace lint policy, starting with disallowing unsafe code where none is required and addressing documentation on supported public boundaries. Do not impose every pedantic lint or ban test unwraps indiscriminately.
- Define supported versus internal APIs despite publish=false. Several public modules expose construction/transform internals or rely on prose-only trust contracts; narrow visibility where downstream use is not intended.
- Preserve raw wire representations only through APIs that maintain their relation to parsed data. A cached second representation requires an enforceable ownership rule.
- Prefer present invariants over milestone labels and refactor history in source comments. Explain the exceptional Scala behavior and its oracle, then put historical development narrative in git or design records.

### Build, CI and release improvements

The release workflow currently depends on successful builds, not on a validation job for the exact tag. Main-branch PR CI may provide good protection, but the release workflow itself does not guarantee that arbitrary/manual tags were validated.

Make an exact-commit validation result a prerequisite to publication. Use --locked in build/test/doc/release commands. Pin third-party action revisions by full commit and automate their updates; mutable major/master references currently remain. GitHub documents [full-commit action pinning](https://docs.github.com/en/actions/reference/security/secure-use) as the immutable reference mechanism.

Pin auditor/install-tool versions as well as their installation lockfiles, or deliberately document a rolling-tool policy. --locked on cargo install locks the selected tool's dependencies; it does not freeze which latest tool version is selected.

Ensure archives have a working quickstart: the packaged README points to repository-relative config/documentation files that the archive does not currently include. Stage an appropriate example configuration and enough operating documentation, and smoke-test both --version/--help and an offline temporary-directory boot.

Either read the Rust version from rust-toolchain.toml throughout CI or validate every duplicated value. Add explicit workspace rust-version metadata if Rust 1.95 is the intended minimum, then inherit it in member manifests; toolchain pinning and compiler requirement communicate different things. [Cargo's manifest reference](https://doc.rust-lang.org/cargo/reference/manifest.html) documents the relevant fields.

Current advisory checks pass with the deliberately accepted bincode-maintenance exception. Duplicate-version warnings alone are not bugs; prioritize those with measurable binary/build/maintenance cost. Replacing established dependencies just to remove warning counts can create more risk than benefit.

### Performance and assurance improvements

Add stable, reproducible benchmark workloads covering parse/serialize, compiler chains, variable-value cloning, Sigma reduction, AVL apply/rollback/persist, mempool admission/revalidation, and API snapshot publication. Track workload dimensions, allocation counts, tail latency, retained/peak memory and disk writes. Use the existing perf reports as a model for recording environment and limits.

Require measurements before changing representations or introducing a VM. For cache changes, quantify hit rate and retained memory rather than assuming more caching improves throughput. For public compute, measure aggregate admission and worker saturation, not only one request's execution cost.

Extend fuzzing to compiler source and small bounded evaluator programs. The structured sigma_expr codec fixed-point surface is not equivalent to executing every generated expression. Keep per-surface generator tests and external-oracle replay; report hermetic and external results separately.

For persistence, add a property/model suite whose state includes foreground tip, queued deltas, committed tip/root, selected header, failure state and shutdown. Generate operations and deterministic scheduling boundaries; assert invariants after every committed step. This targets the actual failure class revealed by the audit.

## Recommended implementation order

1. **Protect persistent state:** F01 and F02, with deterministic failure/interleaving tests before implementation changes. Fix F07 while creating explicit worker shutdown.
2. **Fix resource and configuration contracts:** F03, F04 and F06; investigate R01 with small fixtures and external parity before changing consensus behavior.
3. **Protect wallet lifecycle:** F05 and F08, then secret ownership and commitment API hygiene.
4. **Make public data honest:** F10, F11 and F12; migrate infallible query traits and protect cached representations.
5. **Make lifecycle and load behavior dependable:** F09 and F13; remove node-specific process globals and test same-process restart.
6. **Close assurance gaps:** F15 and F16, external mode/oracle gates, explicit durability tests and exact-tag release validation.
7. **Improve daily development:** simplify entry-point docs, split behavioral test domains, generate inventories, establish focused lint/API policies and reproducible performance baselines.

Keep fixes focused and independently reviewable. Consensus-critical changes need the external oracle evidence required by CONTRIBUTING. For cache/API encapsulation changes, preserve canonical byte identity; for concurrency fixes, test the scheduling boundary that originally violated the guarantee.

The standard to aim for is concrete: every advertised invariant has an owner, an enforceable API boundary, and a meaningful adversarial/failure test; explicit shutdown joins all state-owning work; committed reads never mix foreground and disk state; errors stay errors; release claims are backed by exact-commit evidence. The existing repository has much of the infrastructure needed to reach that standard.

## Confirmed findings

### INDEXER-001 — Public apply/rollback trust stale caller metadata

**P2; REPRODUCED; public storage correctness.** `src/apply.rs:115–150` obtains a writer then checks block height only against supplied meta; it never compares the persisted checkpoint under that lock. `rollback.rs:76–102` checks the caller's header/height before acquiring its writer. Store is Clone and exposed through public Handle::store; serial redb writers cannot validate snapshots acquired before the lock. Ordinary isolated fixture in `benign-probe-final.log` applies one genesis-shaped block twice with IndexerMeta::empty: both succeed with equal returned metadata, ERG balance1000→2000 and box entries1→2 while primary/numeric records overwrite. No node multiwriter/chain incident was demonstrated.

Compare complete persisted meta to caller expectation inside each writer transaction, validate checked counter/height ranges, and enforce exclusive repair/apply ownership or documented explicit low-level API separation. Keep internal multi-block transaction checkpoint advancement valid. Acceptance: stale apply and rollback fail without changes; simultaneous writers/rebuild cannot double-append, overwrite or clear a repair checkpoint; ordinary batch/reorg tests stay green.

### INDEXER-002 — Required v2 metadata defaults hide missing checkpoint fields

**P2; SOURCE_CONFIRMED; local corruption recovery.** `store/meta.rs:216–250` treats absent required height/tx/box keys as0 and absent header asNone. Fresh v2 writes all keys (`store/mod.rs:184–188`), but same-version reopen146–154 does not enforce these fields/invariants. A lost global counter with existing rows can reuse/overwrite numeric indices on the next apply; height>0 with absent header bypasses task divergence. Malformed present widths are correctly rejected. Optional repair markers may remain optional; required checkpoint fields must not silently default on resumed databases.

Validate all required fields and height/header/counter relationships before writable resume; distinguish genuinely fresh initialized zero values. Acceptance: each absent/inconsistent mandatory field yields typed corruption and preserves rows; healthy pre-genesis resumes. This is source-conditional missing durable data, with no disk/power-loss incident demonstrated.

### INDEXER-003 — Chain adapter erases read failures into genesis or missing data

**P2; SOURCE_CONFIRMED; production integration Q020.** Production `ergo-node/src/indexer_chain.rs:39–60` turns committed-tip Err into(height0,zeroID), and63–124 turns header/section storage errors intoNone. Task213/248/297–300 cannot distinguish these from data: an unchanged indexed header plus failed tip read sets CaughtUp; an error on our-height header read can trigger divergence and, if the later committed-tip canonical read succeeds, permit an unnecessary derived-index rollback. Body storage errors become SectionMissing rather than storage failure classification. Genuine divergent zero-tip fallback holds instead of destructive genesis rollback; this narrower behavior is retained.

Make source methods fallible with separate absent/race/storage outcomes; hold existing data/status on a read failure and report a storage/degraded condition with bounded retry. Acceptance must drive actual production adapter error classification into Task and API gating, prove no false healthy/caughtUp or spurious rollback, and retain ordinary valid fork holdoff. No error injection, destructive run or consensus-state mutation was performed.

### INDEXER-004 — Persistent header races retry without delay

**P2; SOURCE_CONFIRMED; resource/liveness.** Task315–317 returns Race when next header is absent; run466–468 immediately starts another batch and resets retries for every Race. Cancellation is checked every iteration, but that does not bound normal load. Configurable zero idle durations also permit immediate idle polls.

Acceptance: stable source absence yields bounded poll counts and prompt cancel, while real fork races recover. No CPU/OOM/service exhaustion demonstration or numerical workload claim was made.

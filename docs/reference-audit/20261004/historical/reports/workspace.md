### WS-001 — P2 release commit is packaged/published without its required validation dependency

**Category:** release/test evidence. **Status:** SOURCE_CONFIRMED. **Root-cause owner:** workspace release workflow.

Expected contract: release artifacts correspond to an identified revision that passed required format, locked dependency, lint, tests, documentation and policy gates before packaging/publication. Authority: `WORKSPACE.md` release-chain requirements and the repository's correctness/CI contract.

Actual behavior: `.github/workflows/release.yml:38–57` checks out the selected tag/ref and runs only `cargo build --release --bin ergo-node --bin ergo-wallet --target ...`, without `--locked`. The publish job at line 105 depends only on those builds. The ordinary CI workflow is triggered for main-branch pushes, PRs and manual invocation; the release job has no verified exact-commit dependency on it. A tag/manual selected ref can therefore reach packaging/publication without the required gates in this workflow. The manually selected tag is validated only later in the publish job. Repository protection/default permissions are external unknowns, so this does not prove a bad binary has been published or an attacker can create a tag.

Evidence: complete workflow source reads in `root-shared-coverage.json`, independent workspace workflow reread, and `root-shared-review.md`. Root's native packaging/CLI smoke passed its narrow Linux subset and does not replace the missing workflow gate.

Fix direction: resolve and record one immutable release commit, enforce tag/package-version agreement, use locked resolution, and make packaging/publication depend on all required gates for that commit. Pin action/tool references according to an explicit policy and restrict build-job permissions; mutable action references are a trust gap, not evidence of compromise.

Acceptance: an isolated workflow validation where a failing required check or lockfile drift prevents packaging/publication; artifact provenance contains the exact gated commit. Native archive smoke on each claimed target remains separately required. Existing main-branch CI success is insufficient because it is not tied to the selected release revision.

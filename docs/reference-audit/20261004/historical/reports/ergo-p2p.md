### Retained-byte and cancellation ledger

Maximum frame wire size8,194,317; PER_READER_MAX8,259,853 including one65536-byte read; production268,435,456-byte budget has32 large-reader slots. The slot-before-bytes/IP-before-slot order and separate one-read path support the uninterrupted-reader progress argument. Enqueued MeteredPayload owns max(length,1) permits until processing/drop; excess read charge only releases on settlement. A fully prebuffered frame acquires while holding no other permits. EOF/error/drop releases RAII charges and claims; channel shutdown drops payloads. Outbound QueuedFrame covers queued/current writing capacity until drop.

This is not an exact process RSS bound: scratch65536 per connection, header read-ahead up to65544, readbuf capacity may grow near twice admitted initialized bytes, and frame deserialization transiently copies payload while the old allocation exists. Outbound serialization adds one frame. Moreover, EP2P001 permits retained partial buffers outside the shared charge during cancellation/write/resumption wait. A perConnection wire cap still exists; no measured exhaustion or permanent reader deadlock is asserted. Source/scoped caller records in `source-review.md` show this ownership split.

Delivery transitions: request increments one owner count and dedupes existing status; accepted current/late/hedge arrival marks received and clears retry/shadow/allowance/count exactly once. Duplicate Ignore does not mutate counters. Hard timeout increments retry and conditionally penalizes; soft timeout reassigns without penalty. Exhaustion clears retry and returns Unknown rather than permanent Failed. Reassign debits old/credits new and registers old owner as late acceptable, capped2 per request. Proactive hedges add uncounted allowances by documented caller policy. Periodic TTL removes abandoned type/late shadows, but not first/second retry counters (EP2P005). Primary disconnect removes entire ID allowance (EP2P006). Mempool transaction timeout explicitly forgets retry while deliberately allowing a legitimate late response.

## Findings

### EP2P001 — P2 — Cancellation releases permits while a retained partial body remains allocated

Category resource ownership/cancellation; **SOURCE_CONFIRMED**. `connection.rs:435–477,497–532` puts bytes, slot and IP claim in the read_body future, while Connection owns read_buf. NODE `peer_loop.rs:440–452,473–539` cancels that future when outbound recv wins, then awaits write up to30s using the same Connection. Dropped permits release accounting, but neither initialized partial bytes nor buffer capacity are discarded. Resumption must reacquire charge while already retaining those bytes. This contradicts ReadBudget's retained-byte argument and NODE's cancellation-safe accounting comment, without necessarily leaking a permit.

Trigger ordinary outbound traffic during a partial admitted body; all body-consuming modes. Source proves the unpaid retention interval and released slot/IP claim; no custom schedule, measured pressure/DoS or physical crash was executed. Existing bare-header/per-IP cancellation tests assert permits return while task/connection drops, and completed payload settlement is correct. They do not retain a populated Connection through cancellation and writing. Small/header read-ahead and documented capacity overhead are separate baseline costs.

Fix retain body accounting with Connection across cancellation, or deliberately discard/reset bytes in a protocol-safe way before releasing ownership; preserve slot ordering and avoid reacquisition while holding an unsafe partial budget. Regression: existing bounded partial-body fixture with outbound select, assert charged initialized bytes remain covered while write is pending, then read resumes, payload transfers and every permit/IP claim returns once. Preserve existing mixed-reader progress positive/negative controls. API/ownership change must retain small-frame fairness; no performance cure inferred from source alone.

### EP2P002 — P2 — Coalesced valid handshake plus frame is rejected by the handshake size check

Category transport interoperability/availability; **SOURCE_CONFIRMED**. `handshake.rs:442–455` explicitly promises a consumed-prefix parser for handshake plus subsequent framed messages, yet checks payload.len()>8096 before determining consumed length. NODE `peer_loop.rs:392–415` passes its entire16384-byte TCP read and preserves leftover only on success. A valid small handshake followed by a valid initial frame in the same read can total8097..16384 and fail TooLarge; the same bytes split after the handshake can succeed.

Normal TCP coalescing and post-handshake protocol traffic are the preconditions; no hostile invalid handshake is required. Source-reachable bootstrap/peer availability consequence, no captured transport run or full-node interop experiment. Existing TCP handshake test uses framed code75, unlike production's raw exchange, so its PASS does not cover this seam. Fix cap the handshake's consumed prefix/parser reads, allowing unrelated bounded leftover; reject genuine oversized handshake before expensive parsing. Regression raw production handshake plus legal frame, fragmented/coalesced at8096/8097/16384 boundaries, assert identical peer acceptance/leftover and true oversized negative. Preserve the absolute exchange deadline and frame cap.

### EP2P003 — P2 — Every address-book open error quarantines the file as corruption

Fix preserve typed errors and quarantine only established corruption; propagate lock/upgrade/transient IO. Regression on disposable existing fixtures: second open leaves exact file identity/content intact and returns AlreadyOpen, upgrade/IO keep original path, real corruption preserves a unique backup and creates fresh. Native Linux source proof; other native rename/locking behavior unexecuted.

### EP2P004 — P2 — Out-of-range stored timestamps panic instead of being skipped as corrupt rows

Pinned Rust1.95 Add calls checked_add.expect; native Unix stores seconds as i64 and rejects larger addition. A structurally valid peer/ban row with an out-of-range timestamp therefore panics before the loader can increment corrupt_skipped (`address_book/mod.rs:319–324,364+`). NODE `node/boot/peers.rs:26–68` handles Result errors best-effort but does not catch that panic, violating its empty-memory fallback contract.

Precondition local semantic row fault/crafted valid DB, not a remotely controllable handshake timestamp or demonstrated physical corruption. Normal writes use valid wall clocks; no DB injection was run. Existing truncated/version/UTF8/corrupt row tests omit time-range overflow. Fix checked_add and return DecodeError on unrepresentable values, applying consistent timestamp/flag/count validation. Regression bounded codec rows at0, native representable boundary and u64::MAX; load must count/skip one invalid row and retain valid peers/bans, with no unwind. Cross-platform SystemTime limits differ; require native platform tests before portability claims.

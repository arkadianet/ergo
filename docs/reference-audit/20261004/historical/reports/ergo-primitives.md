**Category:** testing/documentation; **severity:** P2; **evidence:** SOURCE_CONFIRMED. Owner: primitives comments/test plus validation's active-parameter integration evidence.

**Expected contract and authority:** [cost.rs:48](/home/arkadias/Coding/remote/ergo/ergo-primitives/src/cost.rs:48) says the pin test asserts the live mainnet cap and will fire when a future protocol change raises it. **Trigger/impact:** Maintainers rely on the advertised regression guard during future voted-parameter or cost-model work, in every build/feature mode. A regression must derive the tested cap from the owning parameter source and demonstrably change outcome when that source changes. The current constant-valued unit test cannot provide that evidence.

### EP-002 — Additive-only accumulator contract contradicts deliberate rounding

**Category:** API documentation; **severity:** P3; **evidence:** SOURCE_CONFIRMED. Owner: primitives/codemap; sigma owns caller baseline semantics.

**Expected contract:** [cost.rs:246](/home/arkadias/Coding/remote/ergo/ergo-primitives/src/cost.rs:246) and the crate codemap say the accumulator is additive-only and offers no way to reduce current cost.

**Actual behavior/source proof:** [snap_to_block_boundary:320](/home/arkadias/Coding/remote/ergo/ergo-primitives/src/cost.rs:320) subtracts a remainder0..9 from current. For current19/baseline10 the source expression yields10. A future baseline yields no-op because of `saturating_sub`. The baseline itself is preserved, so a nonmultiple-of-ten baseline can leave a nonaligned global total. **Trigger/impact:** API consumers or reviewers assume monotonic total/consumed cost across every public operation. The contradiction occurs whenever an input's evaluation delta has a remainder, and in all primitive configurations. No evidence establishes an incorrect current caller charge.

**Fix/acceptance:** Describe nonnegative additions plus the explicit per-input truncation operation; document baseline meaning and future-baseline no-op/precondition. Preserve arithmetic/ordering. Add a meaningful direct regression for nonzero baseline and multiple snap/add cycles, and retain independent multi-input JVM acceptance/cost evidence in sigma/validation.
